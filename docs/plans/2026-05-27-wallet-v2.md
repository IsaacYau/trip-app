# Wallet Feature V2 Implementation Plan

> **For Antigravity:** REQUIRED WORKFLOW: Use `.agent/workflows/execute-plan.md` to execute this plan in single-flow mode.

**Goal:** Overhaul the Shared Wallet tab with real-world expense tracking: day-by-day expense dialogs, smart debt settlement, per-person cash tracking, autocomplete on expense title, global split customization, local expense payment methods, locked currency to destination, and enhanced IC card management.

**Architecture:** All changes are confined to `scheduler.html`, `scheduler.css`, and `scheduler.js`. Data model is extended with new fields on expense objects (`day`, `splitAmong`, `splitRatios`, `paymentMethod`) and state objects (`cashBalance`, per-member). No backend schema changes needed — Firestore already stores `state.expenses` as a JSON array.

**Tech Stack:** Vanilla JS, HTML5, CSS3, localStorage + Firestore sync (existing pattern)

## Change Summary by Area

### Area 1 — Remove Simulate Friend Edit
- Remove the `#simulate-sync-btn` button from `scheduler.html`
- Remove its `addEventListener` block in `scheduler.js` (lines 2784–2816)
- Remove the `simulateSyncBtn` const reference (line 737)

### Area 2 — Expense Title: Optional Autocomplete
- Make `expense-title` optional (remove `required`, change label)
- Add a `<datalist id="expense-suggestions">` with common trip keywords
- Keywords: Breakfast, Lunch, Dinner, Snacks, Coffee, Convenience Store, Taxi, Train, Bus, Hotel, Hostel, Museum, Theme Park, Souvenir, Pharmacy, Supermarket, Izakaya, Ramen, Sushi, BBQ, Hot Pot, Dim Sum, Street Food, Bubble Tea
- In JS, hook `input` event on `expense-title` to filter and show suggestions from datalist

### Area 3 — Category as First + Compulsory Field
- In the HTML form, reorder: Category → Expense Type → Expense Title → Amount → Currency → Payer
- Category is already a `<select>`, keep it required (add `required` attribute)
- Expense title becomes the "description" field — optional, appears after category

### Area 4 — Currency Locked to Group Destination
- In `updateDestinationUI()` and on group load, auto-set `expense-currency` value and disable the select
- Japan → JPY only; Malaysia → MYR only; China → CNY only
- Remove manual currency dropdown from the form (or hide it and auto-populate)
- Keep HKD as the secondary display in the ledger and settle-up

### Area 5 — Paid By: All Group Members
- In `updateProfileUI()` and `switchTripNetwork` onSnapshot, populate `#expense-payer` with **all group members** (not just the current user)
- Default selection = current user
- Also populate `#ic-passenger` with all group members

### Area 6 — Global Expense: Split Among + Slider
- When `expense-type = global`, show a new panel `#split-config-panel`:
  - Checkboxes for each group member: "Split among:" with all members pre-checked
  - A range slider per checked member showing their split % (defaults: 2 members → 50/50, 3 members → 33/33/33)
  - Sliders are linked: adjusting one auto-adjusts others to total 100%
  - Store `splitAmong: ["Alice","Bob"]` and `splitRatios: {Alice:50, Bob:50}` on the expense object
- `calculateDebtSettlement` uses these ratios instead of always dividing by 3

### Area 7 — Local Expense: Payment Method
- When `expense-type = local`, show a new panel `#payment-method-panel`:
  - Radio buttons: 💵 Cash | 📱 ePayment | 🚇 Transit Card
  - If Cash: deduct from payer's cash balance; show warning if insufficient cash
  - If ePayment: show sub-radio: AlipayHK | PayMe | Credit Card (info only, no extra logic)
  - If Transit Card: show info note "This will link to Transit Card Estimator"
  - Store `paymentMethod: {type:"cash"|"epayment"|"transit", subType:"alipayhk"|"payme"|"credit"|null}` on expense
- Local expenses remain visible **only to the "paid by" user** when rendered in the ledger
  - In `renderLedger()`, filter: if `exp.type === "local"`, only show if `exp.payer === state.activeUser`

### Area 8 — Day-by-Day Expense Dialog
- Add a day selector row above the expense form: `← Day 1 | Day 2 | ... | Today →`
- "Today" is computed from group destination timezone (JP time for japan, MY time for malaysia)
- Days are trip days (Day 1 = trip start date, or just 1-indexed day labels if no start date set)
- The expense form adds `day: currentDay` to each expense object
- Ledger groups expenses by day with collapsible day headers
- Default selected day = today's trip day

### Area 9 — Cash Balance Tracker
- Add a new section to the right-panel of wallet: "💵 Cash Balance Tracker"
- For each group member, let them input their initial cash amount in the destination currency
- Show running balance: Initial - Cash Expenses Paid
- If balance < 0: show red warning
- State stored in `state.cashBalances = { Alice: { initial: 5000, currency: "JPY" }, ... }`
- Save to localStorage key `travelCashBalances_${groupId}`

### Area 10 — Debt Settlement: Smart Roll-Up + Currency Display
- Debts shown in **destination currency as primary**, HKD as secondary
- Smart debt minimization: use existing greedy double-pointer algorithm but extend it to respect `splitAmong` and `splitRatios`
- The `calculateDebtSettlement` function:
  - For each global expense, credit the payer, debit each `splitAmong` member by their ratio-weighted share
  - Chain debts (A owes B 300, C owes A 400 → C owes B 300, C owes A 100)
- Settlement "Settle Up" button row: user picks Cash or ePayment to clear a debt

### Area 11 — IC Card: Initial Balance Input + Custom Recharge Amount
- Add input field per passenger to set their initial IC card balance (default currently hardcoded as 2000 JPY etc.)
- Add a "Custom Amount" input beside the preset recharge buttons so user can type exact recharge value
- When user types in custom field and presses "Add", recharge that exact amount

### Area 12 — CONVENTIONS.md deletion (already done in branch setup)
